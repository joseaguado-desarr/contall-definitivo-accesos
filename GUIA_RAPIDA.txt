📌 PROBLEMAS IDENTIFICADOS Y RESUELTOS:

1. ❌ VITE_API_URL → URL DE SERVIDOR INCORRECTA
   ├─ Problema: Apuntaba a puerto 3000 pero servidor en puerto 8081
   ├─ Ubicación: .env
   └─ Solución: Cambiar a /api para usar proxy de Vite ✅

2. ❌ CORS NO CONFIGURADO
   ├─ Problema: Restricciones de CORS bloqueaban las solicitudes
   ├─ Ubicación: server/index.js
   └─ Solución: Agregar CORS explícito con orígenes permitidos ✅

3. ❌ ENDPOINT /auth/login FRÁGIL
   ├─ Problema: Usaba JOINs internos que fallaban con datos incompletos
   ├─ Ubicación: server/routes/auth.js
   └─ Solución: Refactorizar con queries separadas y validaciones ✅

4. ❌ ERRORES GENÉRICOS SIN INFORMACIÓN
   ├─ Problema: Mensajes de error no ayudaban a debugging
   ├─ Ubicación: server/routes/auth.js y src/lib/api-client.ts
   └─ Solución: Agregar logging detallado ✅

5. ❌ API CLIENT CON MANEJO DÉBIL DE ERRORES
   ├─ Problema: No manejaba bien respuestas inválidas
   ├─ Ubicación: src/lib/api-client.ts
   └─ Solución: Mejorar parsing de errores y logging ✅

🔍 DEBUGGING (Si aún hay problemas):

1. ¿El servidor está corriendo?
   $ curl http://localhost:8081/health
   Expected: {"status":"ok"}

2. ¿El cliente se conecta correctamente?
   - Abre DevTools (F12)
   - Ve a Network tab
   - Intenta login
   - Verifica que /api/auth/login vaya a http://localhost:8081/api/auth/login

3. ¿El token se guardó?
   - Consola: localStorage.getItem('auth_token')
   - Debe devolver un string largo (JWT token)

4. ¿La base de datos está bien?
   $ cd server && node verify-db.js
   - Verifica: conexión, tablas, usuarios, integridad

5. ¿El endpoint de login funciona?
   $ cd server && node test-login.js <email> <password>
   - Prueba directa sin UI
